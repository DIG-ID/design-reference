# Website Content Playbook — Copywriter & Project Manager Checklists

*Internal standard for web projects. Hospitality / DACH focus. Use as the single source of truth for how content gets planned, written, reviewed and signed off.*

---

## The one rule that fixes 80% of the pain

**Content is a gated phase with a single owner and a sign-off — not a trickle that happens during dev.**

```
Content locked  →  Design locked  →  Dev starts  →  Responsive
        ↑ gate            ↑ gate           ↑ gate
   (approved copy)   (approved comps)  (no scope changes)
```

If content is not approved, design does not lock. If design is not locked, dev does not start. Every time this order is broken, the team ends up reworking and stepping on each other.

For every project, name **one** Content Owner (accountable) and **one** Approver (final "yes"). They can be the same person, but the role must exist.

## PART A — Content & Copy Checklist
*For the person writing/curating content (copywriter or designated content lead). Run per page.*

### 1. Before writing a single word (per page)
- [ ] **Primary goal** defined: inform / convert / rank / support (pick one dominant)
- [ ] **Primary audience** named (leisure guest, corporate/MICE, wedding, wellness…)
- [ ] **Primary conversion action** on the page (Book now, Check availability, Request offer, Call)
- [ ] **Primary keyword + search intent** assigned (from keyword research, not guesswork)
- [ ] **1–3 supporting keywords** / entities
- [ ] Position in the funnel is clear (awareness vs. decision) and copy length matches it
- [ ] Quick competitor glance: what do the top 3 ranking pages actually cover?

### 2. Message & copy quality
- [ ] **One clear message per page** — "what should the visitor think, feel and do?"
- [ ] **Value proposition above the fold** (why *this* hotel, in one line)
- [ ] Benefits before features (not "40m² room" but "room to actually breathe")
- [ ] **Scannable**: short paragraphs (2–4 lines), subheads, bullets — *kills the giant text blocks*
- [ ] Active voice, second person ("you"), concrete language
- [ ] No filler, no jargon, no auto-translated stiffness
- [ ] Consistent terminology (decide once: "rooms" vs "suites", "guests" vs "visitors")
- [ ] Opening line earns the next line (no throat-clearing intros)

### 3. SEO (per page)
- [ ] **Title tag** — ~50–60 chars, keyword front-loaded, brand at the end
- [ ] **Meta description** — ~140–155 chars, includes a reason to click / CTA
- [ ] **URL slug** — short, keyword, hyphenated, no stopwords
- [ ] **Exactly one H1**, then a logical H2 → H3 hierarchy (no skipped levels, no decorative H-tags)
- [ ] **Internal links** to money pages (rooms, booking, offers) with descriptive anchor text
- [ ] **Image alt text** — descriptive, keyword where natural, never stuffed
- [ ] **Structured data** where relevant: `Hotel` / `LodgingBusiness`, `LocalBusiness`, `FAQPage`, `BreadcrumbList`, `Offer`
- [ ] **No cannibalisation** — two pages (or two language versions) aren't fighting for the same keyword
- [ ] Content depth matches intent (a room page ≠ a 2,000-word essay)

### 4. Conversion (CRO)
- [ ] **One primary CTA** per page, unmistakable
- [ ] CTA visible above the fold **and** repeated further down
- [ ] Booking path is one click away (widget, "check availability", phone)
- [ ] **Trust signals** present: ratings, review snippets, awards, certifications, real photos
- [ ] Honest urgency/scarcity only where true (limited packages, seasonal offers)
- [ ] Forms are as short as legally/operationally possible
- [ ] No dead ends — every page points somewhere useful next

### 5. Brand & tone
- [ ] Voice matches the **brand tone guide** (create one if it doesn't exist — even 1 page)
- [ ] Tone matches audience *and* language culture
- [ ] **Formality decided per language** — in German, formal *Sie* vs. informal *du* is a brand decision, applied consistently across the whole site
- [ ] Verbal ↔ visual alignment (copy doesn't fight the design)
- [ ] Terminology glossary respected across all pages
- [ ] Translations are **transcreated, not literal** — a native writes/reviews each language

### 6. Legal & compliance (DACH)
- [ ] **Impressum / Imprint** present and correct (legally required in DE/AT/CH)
- [ ] Privacy policy + cookie consent aligned (no pre-consent firing — check tag manager)
- [ ] Correct legal entity, address, VAT/register info
- [ ] Image & font licensing cleared
- [ ] Accessibility basics met (alt text, contrast, real heading order) — increasingly a legal requirement in the EU
- [ ] Pricing/offer claims are accurate and not misleading

### 7. Pre-publish QA
- [ ] Proofread by a **native speaker per language**
- [ ] No placeholder / lorem ipsum / "TODO" left anywhere
- [ ] All links work; no orphan pages
- [ ] Formatting consistent (capitalisation, punctuation, number/date format per locale)
- [ ] Reads well on mobile (line length, block size)
- [ ] Final Approver has signed off ✅

## PART B — Project Manager / Process Checklist
*For whoever runs the project. This is about ownership, gates and stopping the "everyone on top of each other" problem.*

### Roles (define at kickoff — RACI-lite)
| Role | Responsibility |
|------|----------------|
| **Content Owner** | Accountable for content arriving, in the right shape, on time |
| **Writer / Curator** | Produces or cleans up the copy |
| **Reviewer** | Checks SEO + quality against Part A |
| **Approver** | Final "yes / not yes" — one person |
| **CMS input** | Who actually pastes content in (and it is *not* the client, freestyle) |

### Scope & contract (decide before quoting)
- [ ] Is **copywriting in scope** (we write), out of scope (client writes to a brief), or subcontracted?
- [ ] Whatever the answer — it's **in writing** in the proposal, with responsibilities and deadlines
- [ ] If client provides content: they get a **structured content brief/template**, not a blank page
- [ ] Number of content revision rounds is capped and stated

### Phase gates (enforce the order)
- [ ] Sitemap + page inventory agreed and signed
- [ ] **Content deadline is a hard gate** — with buffer — *before* design lock
- [ ] Design does not lock until content is approved for the key templates
- [ ] Dev does not start until design is locked
- [ ] **No responsive work until desktop is closed** (and vice-versa isn't happening)
- [ ] Each gate has a named owner and a date

### Content brief to the client (so they don't free-write)
- [ ] Per page: goal, audience, key message, must-include facts, word-count range
- [ ] Tone guidance + formality (Sie/du) so they don't invent their own voice
- [ ] Examples of good vs. bad (a filled sample page)
- [ ] A submission format that is easy to review (doc/sheet, not the live CMS)

### Change control (stops the atropelo)
- [ ] After content lock, any change = a **change request**, logged, with a cost/time impact
- [ ] "Small text tweaks during dev" are batched, not done live and ad-hoc
- [ ] Client CMS access, if any, is scoped (staging, or specific fields only)

### Risk / escalation
- [ ] Late-content escalation path defined ("if content isn't in by X, timeline moves by Y")
- [ ] Dependency map so no one starts work that will be invalidated upstream
- [ ] Weekly status on the two things that actually block: content and design lock

### How to actually roll this out
1. Adopt the **gate order** as non-negotiable on the next project.
2. Assign **Content Owner + Approver** at kickoff — even if it's the same person for now.
3. Turn Part A into your review standard and Part C into a template the writer fills per page.
4. Give clients the **content brief** instead of CMS freedom.
5. Decide the **scope question** (we write / they write / we subcontract) and put it in the proposal.

*The checklist matters less than the ownership and the gates. A perfect checklist with no one accountable changes nothing.*
